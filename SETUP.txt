================================================================================
  RESOLUTION DRIFT ARBITRAGE BOT – SETUP & CONFIGURATION GUIDE
================================================================================

Strategy: scan non-crypto markets on Polymarket and Kalshi expiring within the
configured window. When the real-world outcome is already effectively determined
from a hard data source (sports API, FRED, Federal Register) but one or both
platforms haven't priced it in yet, buy the correct side and exit at 80%+ of
theoretical gain or at resolution.

Every credential lives in ONE file: prediction_market_bot/.env
The bot reads it automatically via python-dotenv. Nothing is hardcoded.

--------------------------------------------------------------------------------
STEP 0 – CREATE THE .env FILE
--------------------------------------------------------------------------------

    cp .env.example .env

Open .env and fill in the values below. The file is in .gitignore and must
never be committed to git.


================================================================================
SECTION 1 – KALSHI
================================================================================

Kalshi is a CFTC-regulated US prediction exchange.
Website: https://kalshi.com

--- 1a. Create an account and fund it ---

1. Sign up at https://kalshi.com
2. Complete identity verification (required by US regulations)
3. Deposit USDC

--- 1b. Generate API credentials ---

1. Log in → Account → Settings → API Keys
2. Create New API Key. Label it (e.g. "arb-bot")
3. Copy:
       API Key    – alphanumeric identifier
       API Secret – shown ONCE, save it immediately

--- 1c. Add to .env ---

    KALSHI_API_KEY=<paste>
    KALSHI_API_SECRET=<paste>
    KALSHI_ENV=demo      ← start here; switch to prod when ready

--- 1d. Demo vs Production ---

IMPORTANT: Kalshi's demo environment only has markets expiring 7-30+ days
from now. The core strategy targets markets within 24 hours of resolution.
While testing on demo, set RESOLUTION_WINDOW_HOURS=168 or higher so the
scanner can find markets. Switch both KALSHI_ENV=prod and
RESOLUTION_WINDOW_HOURS=24 together when going live.

    Demo URL : https://demo-api.kalshi.co/trade-api/v2
    Prod URL : https://api.elections.kalshi.com/trade-api/v2

The bot sets the URL automatically from KALSHI_ENV.


================================================================================
SECTION 2 – POLYMARKET
================================================================================

Polymarket is a decentralised prediction market on Polygon.
Website: https://polymarket.com

Two auth layers required:
  L1 – wallet private key (signs on-chain transactions)
  L2 – CLOB API key/secret/passphrase (signs REST requests)

--- 2a. Create and fund a Polygon wallet ---

1. Install MetaMask: https://metamask.io
2. Create a new wallet, save the 12-word seed phrase securely
3. Add Polygon network to MetaMask:
       Network : Polygon Mainnet
       RPC URL : https://polygon-rpc.com
       Chain ID: 137
       Symbol  : MATIC
4. Fund with USDC on Polygon

Your wallet address (0x...) = POLYMARKET_FUNDER_ADDRESS
Your wallet private key     = POLYMARKET_PRIVATE_KEY
  Export: MetaMask → Account details → Show private key
  !! NEVER SHARE THIS. NEVER COMMIT IT. TREAT IT AS A MASTER PASSWORD. !!

--- 2b. Generate CLOB API credentials ---

    python - <<'EOF'
    from py_clob_client.client import ClobClient
    client = ClobClient(
        host="https://clob.polymarket.com",
        chain_id=137,
        key="<YOUR_WALLET_PRIVATE_KEY>",
    )
    creds = client.create_or_derive_api_creds()
    print("API_KEY:       ", creds.api_key)
    print("API_SECRET:    ", creds.api_secret)
    print("API_PASSPHRASE:", creds.api_passphrase)
    EOF

--- 2c. Add to .env ---

    POLYMARKET_API_KEY=<api_key>
    POLYMARKET_API_SECRET=<api_secret>
    POLYMARKET_API_PASSPHRASE=<api_passphrase>
    POLYMARKET_PRIVATE_KEY=0x<wallet private key>
    POLYMARKET_FUNDER_ADDRESS=0x<wallet address>


================================================================================
SECTION 3 – BOT SETTINGS
================================================================================

--- 3a. Core ---

    LIVE_TRADING=false
        Always start here. Logs everything, places nothing.
        Set to true only after verifying paper-trading output looks correct.

    BANKROLL_USD=1000.0
        Total capital. All of it is available for resolution drift trades,
        subject to Kelly sizing and the per-position cap.

--- 3b. Fee cache ---

    FEE_CACHE_TTL_SECONDS=900
        Polymarket is rolling out taker fees to more markets constantly.
        Every order checks the live fee endpoint before execution.
        Cache expires after 15 min (900s). Do not raise above 900.

--- 3c. Resolution window ---

    RESOLUTION_WINDOW_HOURS=168
        Only scan markets expiring within this many hours.
        - Demo testing  : 168 (1 week) or 720 (30 days)
        - Live production: 24 (strategy spec – maximises convergence speed)

--- 3d. Gap threshold ---

    RESOLUTION_MIN_GAP=0.04
        Minimum fee-adjusted probability gap to flag a market.
        4% = if Polymarket says 52% and Kalshi says 56%, that's a 4-point gap.
        Don't go below 3% – noise eats the edge.

--- 3e. Position sizing ---

    RESOLUTION_KELLY_FRACTION=0.12
        Fractional Kelly multiplier. These books are thin. 12% is already
        aggressive for illiquid markets. Range: 0.08-0.15.

    RESOLUTION_MAX_POSITION_FRACTION=0.20
        Hard cap: no single position > 20% of total bankroll.
        Overrides Kelly if Kelly would size larger.

--- 3f. Scan interval ---

    RESOLUTION_SCAN_INTERVAL_SECONDS=300
        How often to run a full scan cycle (default 5 min).
        Lower = more API calls. Don't go below 60.

--- 3g. Monitoring ---

    TELEGRAM_BOT_TOKEN / TELEGRAM_CHAT_ID
        Get token from @BotFather. Get chat ID from @userinfobot.
        Leave blank to disable.

    DISCORD_WEBHOOK_URL
        Create in Server Settings → Integrations → Webhooks.
        Leave blank to disable.

    DAILY_DRAWDOWN_ALERT_PCT=0.05
        Send alert when daily loss exceeds 5% of bankroll.

    MAX_DAILY_LOSS_USD=0
        Hard halt: stop all trading if daily loss exceeds this.
        0 = disabled. Set a real value before going live (e.g. 50.0).


================================================================================
SECTION 4 – INSTALL AND FIRST RUN
================================================================================

1. Install Python 3.11+: https://python.org/downloads

2. Install dependencies:
       pip install -r requirements.txt

3. Single dry-run cycle to verify plumbing:
       python main.py --once --log-level DEBUG

   With Kalshi demo + RESOLUTION_WINDOW_HOURS=168 you should see:
       DEBUG  ResolutionScanner: kalshi raw fetch → 500 markets
       DEBUG  ResolutionScanner: kalshi sample market id=... hours=X.X ...
       INFO   ResolutionScanner: kalshi → N candidates
       INFO   ResolutionBot: cycle done ...

4. Run continuously in dry-run:
       python main.py --log-level INFO

5. Switch to live trading:
       Edit .env: LIVE_TRADING=true, KALSHI_ENV=prod, RESOLUTION_WINDOW_HOURS=24
       Restart: python main.py


================================================================================
SECTION 5 – ARCHITECTURE
================================================================================

    bot.py                   BotCoordinator – owns all infrastructure, runs the bot
    resolution/
      executor.py            Main loop: scan → score → execute → monitor
      scanner.py             Market scanner (window filter, exclusion check)
      gap_detector.py        Cross-platform (>4% after fees) + info signal detection
      confidence.py          Two-dimensional gate: source confidence + resolution clarity
      decay_monitor.py       80% gain → early exit; 50% adverse → stop-loss
    data/ground_truth/
      router.py              Routes market type to correct data source
      sports.py              Sports data APIs (live scores, final results)
      economic.py            FRED API (CPI, Fed rate, payrolls, GDP)
      federal_register.py    Federal Register + CourtListener (regulatory/legal)
    shared/
      fee_cache.py           Per-market fee rate cache (15-min TTL)
      exclusion_list.py      Dynamic market blocklist
      bankroll.py            Capital management + daily halt logic
    monitoring/
      event_db.py            SQLite log (all signals, orders, PnL)
      alerts.py              Telegram / Discord alerts
    config.py                All settings loaded from .env
    main.py                  Entry point + CLI
