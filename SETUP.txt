================================================================================
  PREDICTION MARKET BOT – SETUP & CONFIGURATION GUIDE
================================================================================

This bot runs two independent strategies simultaneously:

  Bot 1 – Maker Rebate Harvester
    Posts two-sided limit orders on Polymarket's 5-min and 15-min crypto
    markets. Earns daily USDC rebates by providing liquidity. Never takes.
    Requires: Polymarket credentials only.

  Bot 2 – Resolution Drift Arbitrage
    Scans non-crypto markets on both Polymarket and Kalshi expiring within
    24 hours. Finds markets where the real-world outcome is already effectively
    determined but not yet priced in. Buys the correct side, exits at 80%+
    of theoretical gain or holds to resolution.
    Requires: Kalshi + Polymarket credentials (or either one alone).

Both bots share: fee cache, exclusion list, bankroll manager, monitoring.

Every credential lives in ONE file: prediction_market_bot/.env
The bot reads it automatically via python-dotenv. Nothing is hardcoded.

--------------------------------------------------------------------------------
STEP 0 – CREATE THE .env FILE
--------------------------------------------------------------------------------

From the prediction_market_bot/ directory:

    cp .env.example .env

Open .env in any text editor. Fill in the values described below.
The file is listed in .gitignore and must never be committed to git.


================================================================================
SECTION 1 – KALSHI (Required for Bot 2 resolution drift)
================================================================================

Kalshi is a CFTC-regulated US prediction exchange.
Website: https://kalshi.com

--- 1a. Create an account ---

1. Go to https://kalshi.com and sign up.
2. Complete identity verification (required by US regulations).
3. Deposit USDC into your account.

--- 1b. Generate API credentials ---

1. Log in → Account → Settings → API Keys (or /settings/api-keys)
2. Click "Create New API Key".
3. Label it (e.g. "arb-bot").
4. Copy both values shown:
       API Key    – alphanumeric identifier
       API Secret – RSA private key (shown ONCE – save it immediately)

--- 1c. Add to .env ---

    KALSHI_API_KEY=<paste your API Key>
    KALSHI_API_SECRET=<paste your API Secret>
    KALSHI_ENV=demo   ← start with demo, switch to prod when ready

--- 1d. Demo vs Production ---

    Demo URL:  https://demo-api.kalshi.co/trade-api/v2
    Prod URL:  https://api.elections.kalshi.com/trade-api/v2

The bot sets the correct URL automatically based on KALSHI_ENV.


================================================================================
SECTION 2 – POLYMARKET (Required for Bot 1 maker + Bot 2 resolution)
================================================================================

Polymarket is a decentralised prediction market on the Polygon blockchain.
Website: https://polymarket.com

Polymarket requires two auth layers:
  L1 – wallet private key (signs on-chain transactions)
  L2 – CLOB API key/secret/passphrase (signs REST requests)

--- 2a. Create and fund a Polygon wallet ---

1. Install MetaMask: https://metamask.io
2. Create a new wallet. Save the 12-word seed phrase securely.
3. Add Polygon network to MetaMask:
       Network name : Polygon Mainnet
       RPC URL      : https://polygon-rpc.com
       Chain ID     : 137
       Symbol       : MATIC
       Explorer     : https://polygonscan.com
4. Fund with USDC on Polygon (bridge from Ethereum or buy on a CEX).

Your wallet address (0x...) = POLYMARKET_FUNDER_ADDRESS
Your wallet private key     = POLYMARKET_PRIVATE_KEY
   Export from MetaMask → Account details → Show private key
   !! TREAT THIS LIKE A PASSWORD. NEVER SHARE IT. NEVER COMMIT IT. !!

--- 2b. Generate CLOB API credentials ---

Use the py-clob-client library (installed with requirements.txt):

    python - <<'EOF'
    from py_clob_client.client import ClobClient
    client = ClobClient(
        host="https://clob.polymarket.com",
        chain_id=137,
        key="<YOUR_WALLET_PRIVATE_KEY>",
    )
    creds = client.create_or_derive_api_creds()
    print("API_KEY:       ", creds.api_key)
    print("API_SECRET:    ", creds.api_secret)
    print("API_PASSPHRASE:", creds.api_passphrase)
    EOF

Copy all three values printed.

--- 2c. Add to .env ---

    POLYMARKET_API_KEY=<api_key from step 2b>
    POLYMARKET_API_SECRET=<api_secret from step 2b>
    POLYMARKET_API_PASSPHRASE=<api_passphrase from step 2b>
    POLYMARKET_PRIVATE_KEY=0x<your wallet private key>
    POLYMARKET_FUNDER_ADDRESS=0x<your wallet address>


================================================================================
SECTION 3 – BOT SETTINGS
================================================================================

--- 3a. Core ---

    DRY_RUN=true
        true  = paper trading, no real orders (always start here)
        false = live trading with real money

    BANKROLL_USD=1000.0
        Your total capital. Bot uses this to size all positions.
        Update to match your actual deposited amount.

--- 3b. Shared infrastructure ---

    FEE_CACHE_TTL_SECONDS=900
        How long fee rates are cached before re-fetching (default 15 min).
        CRITICAL: Polymarket is actively rolling out fees to more markets.
        Every order queries this cache. The cache hits the live fee endpoint
        on miss. Do not raise this above 900.

--- 3c. Bankroll split ---

    MAKER_ALLOCATION_FRACTION=0.60
        60% of bankroll goes to the maker bot (posted as limit orders).
        40% goes to the resolution bot. Must sum to 1.0.

--- 3d. Bot 1: Maker settings ---

    MAKER_ENABLED=true
        Set false to run resolution-only.

    MAKER_HALF_SPREAD=0.010
        Half the spread posted around fair value (1 cent on a $1 binary).
        The bot posts: bid = fair_value - half_spread
                       ask = fair_value + half_spread
        Widen if adverse selection losses exceed rebates over a week.
        Tighten if you're not getting filled enough.

    MAKER_CAP_USD=75.0
        Per-market per-side exposure cap. Start at $50-75.
        If net YES position on a market reaches this cap, stop bidding
        until it rebalances. Prevents one-sided inventory buildup.

--- 3e. Bot 2: Resolution Drift settings ---

    RESOLUTION_ENABLED=true
        Set false to run maker-only.

    RESOLUTION_WINDOW_HOURS=24.0
        Only scan markets expiring within this many hours.
        Shorter windows = higher urgency, faster convergence.

    RESOLUTION_MIN_GAP=0.04
        Minimum probability gap (after fees) to flag a market.
        4% = 4 percentage points (e.g. Poly=52% vs Kalshi=56%).
        Lower = more signals but more false positives. Don't go below 3%.

    RESOLUTION_KELLY_FRACTION=0.12
        Fractional Kelly multiplier for resolution trades.
        12% = 12% of the full Kelly bet size. These markets are thin,
        so stay conservative. Range: 0.10-0.15.

    RESOLUTION_MAX_POSITION_FRACTION=0.20
        Hard cap: no single resolution position > 20% of total bankroll.
        This overrides Kelly if Kelly would size larger.

--- 3f. Monitoring ---

    TELEGRAM_BOT_TOKEN / TELEGRAM_CHAT_ID
        Get a bot token from @BotFather. Get your chat ID from @userinfobot.
        Leave blank to disable Telegram alerts.

    DISCORD_WEBHOOK_URL
        Create an Incoming Webhook in Server Settings → Integrations.
        Leave blank to disable Discord alerts.

    DAILY_DRAWDOWN_ALERT_PCT=0.05
        Send an alert when daily loss exceeds 5% of bankroll.

    MAX_DAILY_LOSS_USD=0
        Hard stop: halt ALL trading if daily loss exceeds this amount.
        0 = disabled. Recommend setting this once you go live (e.g. 50.0).

    SNAPSHOT_INTERVAL_SECONDS=60
        How often portfolio state is written to the event database.

SECTION 4 – INSTALL AND FIRST RUN
================================================================================

1. Install Python 3.11+: https://python.org/downloads

2. Install dependencies:

       pip install -r requirements.txt

3. Verify configuration with a single dry-run resolution cycle:

       python main.py --once --resolution-only --log-level DEBUG

   Expected output:
       INFO  Kalshi client: ENABLED (demo)
       INFO  Polymarket client: ENABLED
       INFO  ResolutionBot: ENABLED
       INFO  ResolutionBot: cycle start
       INFO  ResolutionScanner: N candidate markets within 24h window
       INFO  GapDetector: N cross-platform pairs exceed 4.0% gap
       INFO  ResolutionBot [DRY]: buy_yes <market_id> @ 0.4800 size=$12.00

4. Test the maker bot (watch for quote log lines):

       python main.py --maker-only --log-level DEBUG

   Expected output:
       INFO  MakerBot: ENABLED (half_spread=0.010 cap=$75)
       INFO  FairValueFeed: connecting to Binance ...
       INFO  MakerBot [DRY]: buy BTCUSDT-market @ 0.4800 size=$18.50 → dry_...
       INFO  MakerBot [DRY]: sell BTCUSDT-market @ 0.5000 size=$18.50 → dry_...

5. Run both bots together:

       python main.py --log-level INFO

6. Switch to live trading:
       Edit .env: DRY_RUN=false
       Restart: python main.py


================================================================================
SECTION 5 – RUNNING MODES
================================================================================

    python main.py                  Both bots, continuous
    python main.py --once           Single resolution cycle, then exit
    python main.py --maker-only     Maker bot only (no resolution scanning)
    python main.py --resolution-only  Resolution bot only (no maker quotes)
    python main.py --log-level DEBUG  Verbose output (noisy, good for debugging)
    python main.py --log-file bot.log  Also write logs to file

Platform toggles (in .env):
    KALSHI_ENABLED=false    Skip Kalshi entirely (resolution bot uses Poly only)
    POLYMARKET_ENABLED=false  Skip Polymarket (maker bot requires Poly, so this
                                disables the maker bot too)
    MAKER_ENABLED=false     Disable maker bot without touching .env toggles
    RESOLUTION_ENABLED=false  Disable resolution bot


================================================================================
SECTION 6 – ARCHITECTURE OVERVIEW
================================================================================

    bot.py               BotCoordinator – owns both bots, starts threads
    maker/
      quoter.py          MakerBot – async WebSocket quoting loop
      fair_value.py      Binance bookTicker price feed
      position_tracker.py  Per-market inventory tracking
    resolution/
      executor.py        ResolutionBot – 5-min polling loop
      scanner.py         Market scanner (24h window, non-crypto)
      gap_detector.py    Cross-platform + information gap detection
      confidence.py      Two-dimensional confidence scorer
      decay_monitor.py   Position monitor (80% gain exit, 50% stop-loss)
    data/ground_truth/
      router.py          Routes market type to correct data source
      sports.py          ESPN API (live scores and results)
      economic.py        FRED API (economic releases)
      federal_register.py  Federal Register + CourtListener (regulatory)
    shared/
      fee_cache.py       Per-market fee rate cache (15-min TTL)
      exclusion_list.py  Markets both bots must never touch
      bankroll.py        60/40 capital split + daily halt logic
    monitoring/
      event_db.py        SQLite event log (all signals, orders, PnL)
      alerts.py          Telegram / Discord alerting
    config.py            All settings loaded from .env
    main.py              Entry point + CLI argument parsing


================================================================================
SECTION 7 – PAPER TRADING CHECKLIST (before going live)
================================================================================

Run DRY_RUN=true for at least 2 weeks. Verify:

  [ ] Maker bot is generating quote log lines at < 200ms latency
  [ ] Resolution bot is finding and logging gap signals
  [ ] Fee cache is being queried before every simulated order
  [ ] No markets on the exclusion list are being touched
  [ ] Daily bankroll summary looks correct in logs
  [ ] Alert messages reach Telegram/Discord successfully
  [ ] Bot survives a restart without losing position state
  [ ] Max daily loss limit triggers correctly (test by setting it very low)

Compare simulated fills to what actual order books showed at the same time.
If the maker bot shows frequent adverse selection in dry-run (stale quotes
being "filled"), widen the half-spread before going live.
